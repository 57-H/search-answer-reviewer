# Codex 普通 Skill Beta 可靠性计划

本计划只覆盖用户通过仓库安装到 Codex 的普通 Skill；搜索门控保留为实验性示例，不计入 Beta 承诺。重点风险是搜索结果用于答案前漏审查。普通安装不能机械保证每次触发，因此发布时须公开适用范围、实测覆盖率和剩余漏审。

## 已确定的发布门槛

- 状态为 Beta，首轮只对 Codex 验收；其他 AI 助手标为未验证。
- 以**逐批审查覆盖率**为主指标，技能加载率只用于定位漏审原因。在至少 100 批真实搜索结果中，用于答案或决策前漏审的批次不得超过 5 批；公开分子、分母、测试任务、Codex 版本和运行设置。
- 人工核定的案例中，明显答非所问或缺少关键证据的结果若被当成合格依据使用，属于严重误放行，必须修复后才能发布 Beta。
- 普通模式如显示数量，使用“已审查 x/y”，与实验性门控的“审查通过 x/y”区分。前者是审查覆盖，不代表判断正确或结果通过。

## 已确定的计数口径

1. 一条结果只有完成需求匹配与来源身份判断，并对被用于结论的事实完成核证或明确记录缺口，才计入“已审查”的 `x`。仅扫过标题或摘要不计入。
2. 首轮测试覆盖所有把网页结果用于答案或决策的 Codex 任务，而不仅是某一类问答。

## 当前实现状态

- 普通模式批次记录与 `已审查 x/y` 已由脚本校验和计算，缺失结果保留在分母中。
- 运行轨迹评分已区分技能未加载、审查跳过和审查记录不完整，并检查审查发生在结果使用之前。
- 语义评分已支持人工标注的严重误放行；发布汇总同时检查覆盖率、语义、干净安装和 CI 证据。
- 已加入 Codex 任务集、冻结运行清单示例、文档链接检查、干净安装冒烟检查和 GitHub Actions。
- 尚未完成 100 批真实 Codex 搜索结果测试，也没有可发布的触发率或效果数据，因此当前仍是 Beta 候选。

## 实施顺序

1. **固定可观察的审查契约。** 明确一次搜索批次的边界、`x/y` 的分母和无结果情形。普通模式要留下能够回查的逐批记录；如果报告未生成或结果未经过约定检查，就不能显示“已审查”。更新 `SKILL.md`、schema 与 README，明确门控为实验性示例。
2. **建立干净安装的触发评测。** 从 GitHub 仓库在独立 Codex 环境安装，不沿用开发机的符号链接或当前会话。准备自然表达的搜索任务、连续多轮搜索、已有搜索结果、需要排除候选的任务，以及无需搜索的负例。保存每次工具调用和答案轨迹；用真实搜索结果批次作分母，核对审查是否发生在使用结果之前。失败、超时和未加载技能的运行都保留，不能只统计成功运行。
3. **建立人工核定的语义评测。** 从真实、可公开的案例标注需求匹配、来源身份、关键事实是否有证据，以及严重误放行。保留正确结果和无法访问结果作为对照。比较普通提示与完整 Skill，并记录误报、漏检、额外搜索/模型调用和耗时；现有合成标签不能当作上线效果证据。
4. **只针对实测失败改动 Skill。** 先区分未加载、加载后跳过审查、审查记录不完整、语义误判四类失败，再修改相应触发描述、主流程、校验器或规则。每次修改后在冻结的测试集上重跑，避免只为单个案例增加提示词。
5. **完成发布卫生检查。** 在干净环境验证从仓库链接安装、Python 3.10+ 命令与相对路径；添加自动化测试与文档链接检查；确认 README 的 Beta 范围、实际指标、限制和演示命令一致。达到上述门槛后再打 Beta 标签并发布结果。

## 当前已知缺口

- [评测协议](../eval/protocol.md) 已定义真实运行轨迹、逐批指标和发布门槛，但仓库仍没有完成的 100 批真实运行集。
- 现有语义案例与标签仍是模型草拟的合成材料；需要人工复核并补充真实、可公开案例后，才能用于发布判断。
- [门控代码](../scripts/reviewer_core/gate.py) 仍需要接入方提供真实搜索和审查器；它的单元测试只验证实验性门控行为，不能证明普通安装的触发稳定性。
